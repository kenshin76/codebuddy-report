# Codebuddy 보고서

현재 화면은 **확정 양식 v1.19.7**입니다. 새 LLM 결과는 `models/<id>.json` 한 파일로 추가합니다. 먼저 [모델 추가 안내](UPDATE_MODELS.md)를 읽고, 생성 후 `python3 scripts/build_report.py --check`로 양식과 데이터를 확인하세요. 화면 코드의 직접 수정 없이 모델 수·순위·그래프·표가 갱신됩니다.

표·차트는 핵심 수치와 짧은 명칭·상태를 우선합니다. 긴 해설과 집계 근거는 펼쳐보기로 배치하며, 미수집·관측 소계처럼 해석에 필요한 상태는 수치 가까이에 짧게 남깁니다.

`index.html`이 진입 파일입니다. 빌드·패키지 설치·외부 CDN·네트워크 API 없이 열람하도록 작성했습니다. `data.js`를 일반 스크립트로 불러와 로컬 파일에서 fetch/CORS가 필요하지 않은 구조입니다. 이번 검증 도구는 보안 정책상 `file://` 탐색을 허용하지 않아 직접 파일 열기는 자동 검증하지 못했으며, 아래 로컬 HTTP 방식으로 실제 동작을 확인했습니다.

로컬 HTTP로 확인하려면 이 폴더에서 실행합니다.

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8000`을 엽니다. 서버의 공개 범위를 이 보고서 폴더로 제한하세요.

```sh
python3 scripts/build_report.py
python3 scripts/build_report.py --check
git add .
git commit -m "Update report"
git push origin main
```

## 파일

- `index.html`: 한국어 보고서와 탐색 구조
- `styles.css`: 데스크톱·태블릿·모바일 및 인쇄 스타일
- `models/`: 모델별 점수·토큰·시간·근거 원본 JSON
- `templates/model.example.json`: 미수집을 null로 둔 새 모델 입력 양식
- `report-config.json`: 공통 평가 기준·날짜·대표 기준 모델
- `scripts/build_report.py`: 입력 검증과 데이터 생성
- `template-contract.json`: 확정된 화면 코드의 변경 감지 기준
- `AGENTS.md`, `UPDATE_MODELS.md`: 양식 유지 규칙과 모델 추가 절차
- `data.js`: 모델 원본에서 자동 생성한 브라우저용 데이터
- `app.js`: 상세 화면 전환·모델별 차트·상세 모델·인쇄 동작
- `sources/`: 100점 만점 완성도와 토큰·시간 웹 문서(HTML), Markdown 원본 및 문서 스타일
- `assets/favicon.svg`: 보고서용 텍스트 아이콘. 제품 공식 로고가 아님

## 읽는 방법

완성도 점수는 100점 만점 점수를 사용합니다. 공통 API 통과율은 독립 A01~A40 전체 인수 합격률이 아닙니다. 수치의 근거는 동봉한 두 원문에 있습니다.

토큰은 일반 입력·캐시 읽기·쓰기·출력으로 구분합니다. 추론은 출력에 포함하며 중복 합산하지 않습니다. 관측 범위와 누락·보조 agent 포함 관계를 함께 표시합니다.

핵심 해석은 Kimi·HY4의 보완 후 파일럿 가능성과 DeepSeek의 권한·업무 정확성 재검증 필요성입니다. 결함 상세는 웹 제공 완성도 자료에서 확인할 수 있습니다.

인쇄 버튼 또는 브라우저 인쇄 기능을 사용하면 모든 모델의 비교 그래프와 접힌 상세를 펼친 상태로 출력합니다. A4 가로 인쇄를 기준으로 했으며 페이지 나눔은 브라우저에 따라 다를 수 있습니다.

토큰 그래프는 탭 전환 없이 모델별 개발·검토를 동시에 표시합니다. 토큰 구성 색상과 정확한 수치는 유지하며, HY4 단계 미분류 W2는 두 막대에서 제외하고 상세 표에 보존합니다.

토큰 막대 높이와 구간 간격을 줄이고 모델별 개발+검토 합계를 추가했습니다. HY4는 두 막대의 관측 소계와 단계 미분류 W2 포함 합을 구분합니다. 모든 모델 비교 그래프·표·선택 목록은 Balanced를 마지막에 표시합니다. 인수 기준 표의 열도 모델에 맞춰 함께 재배치합니다.

토큰 비교 그래프의 모델명·수치 영역 폭과 글자 크기를 줄여 중앙 막대 공간을 확대했습니다. 모델별 합계는 오른쪽 개발·검토 수치 아래에 정렬하며, 관측 소계·미수집·HY4의 단계 미분류 포함 합을 구분합니다.

토큰 그래프의 합계와 순위는 청록색으로 구분합니다. 합계 명칭은 생략하고 M 단위 합계는 14px, 순위 글자는 12px로 표시합니다. 정확한 토큰 수는 보조 색상으로 표시합니다. 모델명 아래 번호는 표시한 개발+검토 토큰 합계가 적은 순서이며, 두 구간 중 미수집이 있으면 번호를 붙이지 않습니다. 기존 모델 표시 순서와 Balanced 마지막 배치는 유지합니다. 번호는 관측값 순서이며 모델 효율 순위가 아닙니다.

토큰 그래프 아래 펼쳐보기에 관측값·관측 소계의 차이와 번호 기준을 설명합니다. 오른쪽 합계는 M 단위와 정확한 토큰 수를 함께 표시하며, 합계 아래의 ‘프로젝트 전체 미확정’ 문구는 제거했습니다.

미수집 모델은 토큰 그래프의 합계·빈 하단 영역을 생략하고 개발·검토 행 간격을 줄입니다. 그래프 아래 기본 안내는 합산 기준과 M 단위 설명만 표시합니다.

소요 시간도 토큰 그래프와 같은 모델별 개발·검토 두 막대, 공통 분 단위 눈금, 오른쪽 구간 합계로 표시합니다. 번호는 표시 구간 합이 짧은 순서이며 속도·효율 순위를 의미하지 않습니다. Balanced는 새 실행의 개발·검토 기록과 합계·번호를 표시하며 마지막 배치는 유지합니다. 정확한 시간표와 측정 한계는 펼쳐보기에 보존합니다.

탐색은 5개 큰 메뉴(핵심 요약 / 성능 비교 / 비용 비교 / 도입 판단·근거 / 부록)로 구성합니다. 성능 비교는 결론 / 완성도·API 통과율 / 토큰·소요 시간, 도입 판단·근거는 평가 방법·근거와 결론·다음 단계의 하위 메뉴를 제공합니다. 화면에는 선택한 상세 하나만 표시하며 기존 섹션 해시 링크·뒤로/앞으로 이동·원문 링크를 유지합니다. 인쇄/PDF 저장 시에는 모든 섹션을 출력합니다.

완성도 그래프는 모델마다 점수·API 통과율 두 막대를 같은 0–100 눈금으로 표시합니다. 두 지표를 합산하지 않으며, 전환 버튼과 비교 범위·정렬 드롭다운 없이 전체 모델을 고정 순서로 보여줍니다.

성능 비교 요약 표는 점수와 아래의 API 통과율·M 단위 토큰 사용량과 정확한 토큰 수·시간/분 단위 소요 시간·짧은 활용 판단으로 구성합니다. 점수 막대와 셀 안의 긴 설명은 제거하고 모델별 근거를 펼쳐보기로 제공합니다. 수치 집계는 유지하며 시간의 초 단위만 생략합니다.

도입 판단·근거는 평가 기준과 모델별 권고를 간략하게 표시합니다. 채점식·수집 한계·후속 실험 조건은 펼쳐보기에 보존하며, 결함과 도입 조건의 별도 화면·메뉴는 제공하지 않습니다.

근거 자료 버튼은 `sources/보고서_완성도.html`과 `sources/보고서_사용량.html`로 연결합니다. 자료 출처·SHA-256 펼쳐보기는 화면에서 제거했습니다. 자료 본문을 수정한 뒤에는 Markdown 3.7이 설치된 Python에서 `python3 scripts/render_sources.py`를 실행해 HTML을 갱신합니다. 렌더링 도구는 개발 시에만 필요하며 웹 문서 열람에는 설치·네트워크가 필요 없습니다. 로컬 파일 경로는 링크 대신 참조 텍스트로 표시합니다.

모델 추가 검증: `python3 scripts/test_report.py`. 새 모델의 표 확장, 미수집과 실제 0, 동점 순위, 중복 ID·잘못된 토큰 합계 차단, 기존 모델 보존, 양식 변경 감지를 확인합니다.

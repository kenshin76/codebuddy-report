    점수의 7개 구성 영역을 확인하세요.

    A항목 표의 C=정적 충족 추정, P=부분, M=누락, D=위반, —=독립 NOT_RUN. C를 실행 PASS로 바꾸지 않았습니다.

    효율 비교가 가능한 관측 범위를 확보한 모델에만 적용합니다. 캐시·도구·개발일 차이를 통제한 인과 비교나 전체 모델의 효율 순위가 아닙니다.

    점수 / 100만 토큰 = 점수 × 1,000,000 ÷ 관측 토큰
    점수 / 1시간 = 점수 × 3,600,000 ÷ 두 요청 경과 ms 합

    크레딧 기준 모델

    DeepSeek·HY4·Kimi·Balanced는 ‘보고서_사용량.md’의 HRMS 개발·검토 크레딧에 $40 ÷ 선택한 지급 크레딧량을 적용합니다. 기본 1,000에 보너스 1,000, 활동 보너스 최대 1,500을 각각 더하는 비교 가정입니다. 활동 보너스는 30일 조건 충족 기준이며 실제 요금제별 지급 보장을 뜻하지 않습니다. 기록된 사용 크레딧은 그대로 유지하며, 비용 화면의 두 옵션은 요금제 화면과 독립적으로 동작합니다.

    토큰 기준 모델

    GPT·Opus는 사용자가 제공한 구독요금 ÷ (주당 토큰 지급량 × 4.3주) 산정 기준과 지정 단가를 사용합니다. Opus는 $0.214/1M, GPT는 $0.3145/1M이며, 개발·검토 각각의 합계 토큰 ÷ 1M × 단가로 계산합니다. 주당 표시량을 그대로 계산하면 Opus 약 $0.213356, GPT 약 $0.314268이지만, 이 화면의 적용 단가는 요청한 지정값을 유지합니다. 실제 청구액이나 보장된 최저가를 뜻하지 않습니다.

    • 크레딧은 현재 토큰 그래프와 같은 개발·검토 범위로 맞췄습니다. HY4 W2 미분류·W4 문서, 별도 UI, 포함·중복 미확인 agent 소비는 합산하지 않습니다.
    • 기록된 관측 범위의 환산액이며 실제 청구액·프로젝트 전체 비용은 미확인입니다. 토큰 기준 모델은 사용자 지정 단가를 캐시 포함 합계 토큰에 적용합니다. 과거 리뷰 시험의 한도 사용률 배분 단가는 현재 비용 계산에 사용하지 않습니다.

    Pro의 할인 제외 $20/월은 취소선 참고값이며 정상 청구가는 미확인입니다. 프로모션을 켜면 문서의 Pro 표시가 $10/월을 적용합니다. Team은 $40/좌석·월로 동일합니다.

    제공량은 크레딧입니다. Pro는 30일 활동 조건 충족 기준 최대값, Team은 확인된 월 정기 제공량입니다.

    가격·할인·보너스의 적용 기준
    • 기본 비교: Pro는 문서10절의 할인 제외 참고값 $20/월, Team은 $40/좌석·월입니다. 기본 제공량은 각각 월1,000크레딧이며 세 옵션은 처음에 꺼져 있습니다.
    • 프로모션: 월 결제 Pro에 문서의 표시가$10을 적용합니다. Team의 월 요금은$40으로 유지합니다. 연간구독을 함께 켜면 기존 연 결제 표시가인 Pro 월 환산$8·연$96을 사용하며 가격 할인을 중복 적용하지 않습니다.
    • 연간구독: 문서2절의 연 결제 표시가를 사용합니다. Pro는 연$96(월 환산$8), Team은 연$480/좌석(월 환산$40)입니다. Pro의20% 할인은 표시 월 가격$10 대비이며 취소선 참고값$20 대비 할인율이 아닙니다. Team의 연 할인율은0%입니다.
    • 보너스: 옵션을 켜면 Pro·Team 모두 월1,000크레딧을 한 번만 더해 각각 월2,000크레딧을 표시합니다. Team은 기간 한정 프로모션이며, Pro는 문서에 한정 표시가 없지만 지속 여부는 미확인입니다. 연 결제라도 월 단위 지급량을 표시합니다.
    • 일일 활동: Pro는 보상 대상 활동일당50크레딧이 별도로 표시되어 있습니다. Pro는 기본 + 30일 활동보상 + 선택 보너스 순서로 최대 합계를 표시합니다. 30일 모두 보상 조건을 충족하면50×30=1,500크레딧이 추가되어 보너스 제외2,500·포함3,500크레딧이며 실제 잔액·보장 지급량은 아닙니다. Team의 일일 보상은 미표기입니다.

    7개 영역의 잠정 평가

    모델별 결과물은 각 1개입니다. 점수와 API 통과율이 전체 인수 합격을 의미하지는 않습니다.

    평가 범위와 미실행 항목
    • 공통 명세: HRMS.md 1.9 · R8. 루트와 비교 대상 6개 사본의 SHA-256이 일치합니다.
    • 평가 시점과 범위: 기존5개는11월24일 평가를 보존했습니다. Balanced는11월25일 직접 텍스트93개와 실행 환경을 확인했습니다. 공통 HTTP111개 실행·1개 미실행이며 화면은1440px에서 확인했습니다. 전체 역할·변경 흐름은 미검증입니다. 기존 JUnit XML과 개발자 PASS 주장은 독립 실행 결과와 구분했습니다.
    • 점수 해석: 소스·설정·화면을 함께 검토한 정성 점수입니다. Opus 5.5와 GPT-6.1-sol의 1점 차이는 유지보수성 판단에 민감합니다. 기반 모델 전체의 성능을 증명하는 통계 실험은 아닙니다.
    • 미실행: 유효한 인사·근태·연차 변경, 동시성, 장애 복구, 새 볼륨 기동, 전체 역할 UI. 미검증을 PASS로 처리하지 않았습니다.
    배점과 계산식

    API 통과율 = PASS ÷ 실행 수(미실행 제외) · A 검증 커버리지 = (PASS + FAIL) ÷ 40
    정적 구현 추정율 = (C + 0.5 × P + 0.5 × D) ÷ 40

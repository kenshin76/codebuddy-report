11-20 시험 모델의 값은 리뷰 10건 금액을 캐시 읽기를 뺀 토큰으로 나눈 근삿값이다. 금액은 CodeBuddy 행이 보고서에 표시된 구독 환산액과 OpenRouter 추정액, Claude 행이 보고서의 주간 한도 사용률(0.81%·0.41%)로 다시 계산한 구독 환산액과 실행 기록의 비용이다. 이 사용률은 소수 둘째 자리까지라 Claude 행 구독 환산액의 셋째 자리는 근삿값이다. 보고서 토큰 표의 입력은 Claude·CodeBuddy 모델에서 캐시 읽기를 포함하므로, 보관한 실행 기록의 캐시 읽기(Claude `cache_read_input_tokens`, CodeBuddy `cached_tokens`)를 빼고 다시 셌다. `deepseek-v4.1-flash`·`minimax-m3.1-flash`·`hy4flash-free`는 1회차 A~E 실행 기록이 남아 있지 않아, 남은 15회의 캐시 읽기 비율로 추정했다. ChatGPT 모델은 원장의 일반 입력이 이미 캐시 읽기를 뺀 값이고, 구독 환산액과 OpenRouter 값 모두 원장 기록으로 다시 계산했다. `fast-model`·`balanced-model` 행은 11-25 실행 기록 20회씩으로 계산했고, 실제 답하는 모델이 공개되지 않아 OpenRouter 추정액은 비워 두었다. Jira 하단의 `token-ledger` 사용량은 일감 전체 집계다. 100만 토큰당 비용은 입력·출력 비율과 캐시 사용량에 따라 달라진다. [보고서 비용·토큰 표](2026-11-20-model-comparison-report.md#비용과-토큰-사용량)

### `gpt-6.1-sol` 추가 시험과 `gpt-6.2-sol` 시험 비교

같은 입력에서 `gpt-6.1-sol`은 100만 토큰당 $0.31로, `gpt-6.2-sol` 시험의 $0.34보다 약 6% 낮았다. 두 모델의 단가가 같아서 차이는 토큰 구성에서만 나온다. 100만 토큰당 금액은 모델끼리 비용을 비교하는 값이 아니다. 비용은 리뷰 1건당 금액으로 비교하며, 리뷰 10건 구독 환산액은 `gpt-6.1-sol` $0.215, `gpt-6.2-sol` $0.238로 `gpt-6.2-sol`이 약 11% 더 든다. 입력은 거의 같고 출력이 75% 많았다. 이번 시험은 지적 내용의 블라인드 판정 없이 비용만 계산했다.

시험 조건

- 입력: 보관 폴더 `replay/`의 A~J 프롬프트 10건. SHA-256이 기존 `gpt-6.2-sol` 실행 메타데이터 20건의 `prompt_sha256`과 모두 일치함.
- 실행: Claude에서 `review-run` 래퍼로 Codex CLI 호출(codex-cli 0.169.0, 기존 시험과 같은 버전). 임시 `REVIEW_MODELS`로 `gpt-6.1-sol` high 지정. 리뷰 10건씩 2회, 실행마다 새 빈 작업 폴더 사용.
- 도구 미사용: 20회 모두 Codex 로그에 명령 실행·MCP 호출이 없고, 끝난 뒤 작업 폴더도 비어 있음. 20회 모두 `status: ok`.
- 원장: `token-ledger sync` 뒤 세션 20개, 요청 20개. 실행 메타의 토큰 수와 원장의 일반 입력 + 출력이 20회 모두 일치함.
- 산출물: `~/.claude/review-trial-archive/2026-11-20-model-compare/sol61/` (계산 스크립트 `cost.py` 포함).

계산식

1. 원장 가중치 = (일반 입력 × $2 + 출력 × $10 + 캐시 읽기 × $0.10) ÷ 1,000,000. 원장의 일반 입력은 이미 캐시 읽기를 뺀 값이라 그대로 씀. 이 값은 원장에 기록된 가중치와 같음.
2. 주간 한도 사용률(%) = 리뷰 10건 가중치 ÷ 1%당 가중치 $1.65
3. 구독 환산액 = 좌석 월 $100 ÷ 4.3주 × 주간 한도 사용률
4. 100만 토큰당 환산액 = 구독 환산액 ÷ (일반 입력 + 출력) × 1,000,000. 분모에 캐시 읽기는 넣지 않음.

예: `gpt-6.1-sol`은 $1.52721 ÷ $1.65 = 0.92558%, $23.2558 × 0.92558% = $0.21525, $0.21525 ÷ 684,334.5 × 1,000,000 = $0.3145.

리뷰 10건 가중치는 20회 합계를 2로 나눈 값이다.

OpenRouter 추정액은 `GET /api/v1/models/openai/gpt-6.1-sol/endpoints`의 OpenAI 기본 공급 행(`service_tier` 없음, `discount` 0) 단가로 계산했다. 일반 입력 $2, 출력 $10, 캐시 읽기 $0.10으로 원장 가중치 단가와 같고, 11-20에 보관한 모델 목록의 `gpt-6.1-sol` 단가와도 같다. 요청당 입력은 최대 165,789토큰이라 272,000토큰 이상에 붙는 할증 단가는 적용되지 않는다. 그래서 OpenRouter 추정액은 원장 가중치와 같고, 100만 토큰당 값은 `$1.5272 ÷ 684,335 × 1,000,000 = $2.23`이다. flex·priority 공급 행은 쓰지 않았다.

### CodeBuddy `fast-model`·`balanced-model` 추가 시험

`fast-model`은 리뷰 10건에 16.6 credit($0.665), `balanced-model`은 94.1 credit($3.76)을 썼다. 100만 토큰당으로는 $0.93과 $4.80이다. `fast-model`은 `minimax-m3.1-flash`(16 credit)와 비용이 비슷하고, `balanced-model`은 `deepseek-v4.1-flash`(52 credit)의 약 1.8배다. 앱에 표시된 credit 배율은 Fast x0.34, Balanced x0.59로 1.7배 차이지만, 실제 사용량은 5.7배 차이였다. 이번 시험은 지적 내용의 블라인드 판정 없이 비용만 계산했다.

두 모델은 CodeBuddy가 정한 별칭이라 실제로 답하는 모델을 알 수 없다. 응답 기록의 모델 이름도 `fast-model`·`balanced-model`로만 남는다. 같은 프롬프트의 입력 토큰 수도 두 모델에서 달랐지만(A 기준 24,451과 26,776), 앱이 모델마다 다른 시스템 프롬프트를 붙였을 수도 있어 실제 모델이 다른지는 확인하지 못했다. 별칭이 가리키는 모델은 CodeBuddy가 바꿀 수 있으므로, 이 결과는 2026-11-25 시점 값이다.

계산식

1. 리뷰 10건 credit = 20회 credit 합계 ÷ 2
2. 구독 환산액 = 리뷰 10건 credit × $0.04
3. 100만 토큰당 환산액 = 구독 환산액 ÷ (입력 − 캐시 읽기 + 출력) × 1,000,000

예: `fast-model`은 33.27 ÷ 2 = 16.635 credit, 16.635 × $0.04 = $0.6654, $0.6654 ÷ 717,356 × 1,000,000 = $0.93.

리뷰 10건 토큰 값은 20회 합계를 2로 나눠 정수로 반올림했다. 그래서 `balanced-model`은 표의 입력 − 캐시 읽기 + 출력을 더하면 783,575이고, 반올림 전 값은 783,574.5다.

`minimax-m3.1-flash`·`deepseek-v4.1-flash` 열은 위 100만 토큰당 비용 표와 보고서의 [비용 표](2026-11-20-model-comparison-report.md#비용과-토큰-사용량)·[시간 표](2026-11-20-model-comparison-report.md#리뷰-시간) 값이다. 앱 표시 credit 배율은 CodeBuddy가 로컬에 저장한 모델 목록의 값이고 실제 사용량과 다르다. `deepseek-v4.1-flash`는 x0.00으로 표시되지만 52 credit을 썼다. 평균 시간은 두 모델을 동시에 돌린 값이라 11-20 시험과 실행 환경이 같지 않다.
